1. Project Overview

Thekaydaar.pk is a multi-role construction marketplace built in Flutter. It connects Clients (Maaliks) who post construction projects with Thekaydaars (Contractors) who bid on them, managed under tiered administrative oversight. The platform covers the full engagement lifecycle: project posting, bidding with a Connects credit system, real-time chat, contract generation (PDF), billing and payments, ratings, and a built-in AI House Planner that generates 2D blueprints, procedural 3D views, and 360° panoramas — fully functional offline via a rule-based planner, with optional Gemini AI enhancement.

2. Key Features

Feature Description
🏠 AI House Planner Generates complete house plans from plot details — 2D blueprint, procedural 3D projection, and first-person 360° panorama. Works fully offline via the built-in rule-based planner; Gemini AI is an optional enhancement.
📋 Projects & Bidding Clients post construction projects with location details; contractors browse open projects and submit bids.
💬 Real-time Chat Firestore-powered messaging with image sharing via Cloudinary.
📄 Contract Management Contract + scope-of-work creation with PDF generation, printing, and sharing.
💳 Billing & Payments Payment tracking and payment history per project.
⭐ Ratings & Reviews Clients rate contractors after project completion; ratings shown on public profiles.
🗺️ Maps & Location Google Maps location picker with automatic city/area detection (multi-level geocoding fallback).
🔔 Messages & Notifications In-app notification center for project and chat activity.
🌐 Bilingual Support English / Urdu translation service with Jameel Noori Nastaleeq font.

3. User Roles

Role Capabilities
Client (Maalik) Post projects, generate AI house plans, review bids, accept bids, chat, sign contracts, make payments, rate contractors.
Thekaydaar (Contractor) Browse projects, place bids (spends Connects), view blueprint dimensions, chat, manage active jobs, complete work.
Super Admin Full platform control; reviews and approves pending admin sign-up requests.
Regional Admin Regional administrative dashboard and oversight.
Support Desk Handles support requests and ticket workflows.

Aspect Detail
Source of truth Structured plan JSON (HousePlan model, feet internally)
Offline-first Rule-based planner works with no API key — Gemini only enhances
Reliability Remote → validate → repair → local fallback chain
Versioning Every regeneration stored under house_plans/{id}/versions/{n}
Role gating Client sees 2D / 3D / 360°; contractor sees dimensions sheet only
Privacy project_blueprints is a sanitized projection — no 3D/panorama URLs, enforced by firestore.rules

10. Connects & Monetization

Connects are the bidding currency for Thekaydaars.

Plan activated ──► monthly connects granted ──┐
Buy connects package ─────────────────────────┤──► users doc balance
Monthly expiry check ─────────────────────────┘
                     │
Thekaydaar places bid
      │
      ▼
Firestore transaction
      ├── Plan allows bidding?  ── No ──► Upgrade plan
      ├── Balance covers cost?  ── No ──► Buy more connects
      │        │ Yes
      ▼        ▼
Deduct plan connects first, then purchased
      │
      ▼
connects_transactions ledger record
Rule Detail
Bid cost Computed from the project's budget range
Deduction order Plan connects first, then purchased connects
Free plan Cannot bid — upgrade required
Expiry Plan connects expire monthly; purchased connects persist
Ledger Every grant / purchase / spend recorded in connects_transactions

13. Security Model

Control Enforcement
Secrets in .env Loaded at runtime; .env, google-services.json, firebase.json, local.properties all git-ignored; only placeholder .example templates are committed
AI plan privacy Firestore rules block contractor access to house_plans; only sanitized project_blueprints is readable
Connects integrity Balance checks + deduction inside a single Firestore transaction
Admin access Super Admin gated via SUPER_ADMIN_EMAIL; admin accounts require approval (accountStatus)
Maps key Injected at build time from android/local.properties via manifest placeholders

14. Getting Started

Prerequisites

  • Flutter SDK (Dart ^3.10.4)
  • A Firebase project with Authentication, Cloud Firestore, and Storage enabled
  • (Optional) Gemini API key, Cloudinary account, Google Maps API key

Setup Steps

  1. Clone: git clone https://github.com/KashifDev4you/ThekayDaar-AI.git
  2. Install dependencies: flutter pub get
  3. Copy environment template and fill values: Copy-Item .env.example .env
  4. Copy Firebase templates: android/app/google-services.json.example → google-services.json; firebase.json.example → firebase.json
  5. Add Maps key to android/local.properties: GOOGLE_MAPS_API_KEY=your_key
  6. Run: flutter run
